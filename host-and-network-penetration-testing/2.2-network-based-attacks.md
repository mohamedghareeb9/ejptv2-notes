# 2.2 Network-Based Attacks

**Domain:** Host & Network Penetration Testing  

**Status:** study notes | lab or explicitly authorized networks only

## 1. Network foundations

### IP and MAC addresses
- IPv4 addresses are 32 bits; IPv6 addresses are 128 bits.
- An IP address identifies an interface at the network layer and is used for routing between networks.
- A MAC address identifies a network interface on a local link.
- Routers forward packets between networks and replace link-layer framing at each hop; source and destination IPs normally remain end-to-end unless translation is involved.

### ARP
ARP resolves an IPv4 address to a MAC address on the local network segment. A device broadcasts a request asking which host owns an IP; the matching host replies with its MAC. Hosts cache these mappings.

~~~bash
ip -br address
ip neigh
arp -a
~~~

ARP is a local-link protocol. It does not resolve a remote internet host's MAC address across routers.

### DNS
DNS translates names into records used to locate services.

| Record | Meaning |
|---|---|
| A | Name to IPv4 address |
| AAAA | Name to IPv6 address |
| CNAME | Alias to another name |
| MX | Mail exchanger |
| NS | Authoritative name server |
| TXT | Text data, often verification and email policy |
| PTR | Reverse lookup: address to name |
| SOA | Zone authority and timing/serial information |

~~~bash
dig example.com A
dig example.com MX
dig example.com NS
dig +short example.com
nslookup example.com
~~~

### TCP and UDP
| TCP | UDP |
|---|---|
| Connection-oriented | Connectionless |
| Reliable, ordered byte stream | No built-in delivery or ordering guarantee |
| Uses a three-way handshake | No TCP-style handshake |
| More connection state and overhead | Lower protocol overhead |

TCP connection establishment: client sends SYN, server responds SYN-ACK, client sends ACK.

Common ports to recognize:

| Port | Common service |
|---:|---|
| 21 | FTP |
| 22 | SSH |
| 23 | Telnet |
| 25 | SMTP |
| 53 | DNS |
| 80 | HTTP |
| 110 | POP3 |
| 139 | NetBIOS session service |
| 143 | IMAP |
| 443 | HTTPS |
| 445 | SMB |
| 3306 | MySQL |
| 3389 | RDP |

A port number is an indicator, not proof of which service is running. Confirm by enumeration.

## 2. Routing, ASN, and boundaries
A default gateway is the next-hop router a host uses when the destination is outside its local subnet. A subnet mask/CIDR prefix determines which addresses are considered local.

An Autonomous System (AS) is a network or group of networks managed under a common routing policy. An ASN identifies that AS in inter-domain routing. BGP exchanges reachability information between autonomous systems.

ASN and announced IP ranges can help map an organization's public network footprint. Verify ownership and scope before scanning discovered ranges.

## 3. Common network services
- **FTP:** file transfer; traditional FTP does not encrypt credentials or data.
- **SSH:** secure remote administration; protect it with strong authentication and access restrictions.
- **Telnet:** remote terminal access without transport encryption.
- **SMB:** file, printer, and resource sharing, commonly associated with TCP 445.
- **RDP:** remote desktop access, commonly associated with TCP 3389.
- **HTTP/HTTPS:** web services; HTTPS uses TLS to protect traffic in transit.
- **SMTP, POP3, IMAP:** email transport and retrieval roles.
- **MySQL:** database service; avoid broad exposure without a requirement.

An open port is not itself a vulnerability. Determine service, version, configuration, authentication requirements, and expected reachability.

## 4. Network attacks and defensive concepts

### Sniffing
Packet sniffing captures traffic visible to a network interface. It can identify hosts, protocols, connection patterns, and cleartext data. The practical notes use Wireshark and display filters.

~~~text
ip.addr == 192.168.1.10
tcp
udp
dns
http
arp
~~~

A capture filter is applied while capturing; a display filter changes which already-captured packets are shown.

### Man-in-the-middle
A MITM position allows an attacker to intercept or relay communication between parties. The practical notes connect this risk with local network behavior, rogue DHCP, and traffic redirection. Encryption and certificate validation help protect application data, but do not make every endpoint or network trustworthy.

### ARP spoofing / poisoning
ARP has no built-in authentication. On a vulnerable local network, forged ARP replies can cause devices to associate an IP address with an attacker's MAC address, redirecting local traffic.

Defenses include Dynamic ARP Inspection where supported, DHCP snooping as an input to trusted bindings, network segmentation, and monitoring for unexpected ARP changes.

### DHCP attacks
DHCP automatically provides network configuration to clients, commonly an IP address, subnet mask, default gateway, and DNS server. It normally uses UDP port 67 on the server and UDP port 68 on the client.

The basic DORA exchange is:

1. **Discover:** the client broadcasts to find a DHCP server.
2. **Offer:** a server offers an address and configuration.
3. **Request:** the client requests the offered configuration.
4. **Acknowledge:** the server confirms the lease.

A **scope** is the address range a DHCP server can allocate. A **lease** is the time for which a client may use an assigned address. A **reservation** associates a particular client (commonly by MAC address) with a consistent address. Because the initial discovery uses broadcast, routers do not normally forward it between subnets; a **DHCP relay** forwards the request to a server on another network.

A rogue DHCP server may provide malicious gateway or DNS settings. DHCP starvation attempts to exhaust the lease pool. DHCP snooping and trusted switch ports are defensive controls discussed in the practical notes.

### Denial of service
A denial-of-service attack attempts to make a service unavailable by exhausting a resource or overwhelming a service. The practical notes mention SYN floods as a TCP-related risk. Recognition and defensive understanding are the focus; do not run disruptive tests outside a controlled lab.

## 5. Network security controls and infrastructure

### Firewalls

A firewall controls traffic between network zones according to configured rules. Depending on its type, it may inspect source and destination addresses, ports, protocols, connection state, applications, or user identity. Rule order and the default policy matter: a broad allow rule can expose services that the organization intended to restrict.

| Type | Main characteristic |
|---|---|
| Packet-filtering | Filters using fields such as IP addresses, ports, and protocols; traditional forms are stateless |
| Stateful | Tracks connection state and evaluates packets in the context of established connections |
| Circuit-level gateway | Validates session establishment without deeply inspecting application payloads |
| Application proxy | Acts as an intermediary and can inspect application-layer traffic |
| Next-generation firewall (NGFW) | Combines stateful filtering with application awareness and may integrate IDS/IPS, malware detection, VPN, or web filtering |

A firewall reduces exposure; it does not fix weak passwords, secure vulnerable applications, or replace endpoint protection.

### IDS and IPS

- **IDS (Intrusion Detection System):** monitors activity and generates alerts about suspicious behavior. It is commonly deployed out-of-band.
- **IPS (Intrusion Prevention System):** can actively block or reject detected malicious traffic and is commonly deployed inline.

Memory aid: **IDS detects; IPS detects and can prevent.** Actual capabilities depend on the product and configuration.

### Endpoints and EDR

An endpoint is a device connected to a network, such as a workstation, server, laptop, phone, or virtual machine. Its attack surface includes exposed services, installed software, operating-system vulnerabilities, and user permissions.

Traditional endpoint controls include antivirus, host firewalls, and updates. **EDR (Endpoint Detection and Response)** adds endpoint behavior monitoring and investigation/response capabilities, such as alerting, terminating a process, or isolating a host. EDR is not simply another name for antivirus.

### Load balancers

A load balancer distributes incoming client connections or requests across backend servers to improve availability and performance.

| Method or layer | What to recognize |
|---|---|
| Round robin | Distributes requests in rotation |
| Least connections | Prefers the server with the fewest active connections |
| Weighted balancing | Sends a larger share of traffic to servers with higher assigned capacity |
| IP hash | Uses the client IP to select a backend; may support session persistence |
| Layer 4 | Makes decisions using transport information such as IP addresses and TCP/UDP ports |
| Layer 7 | Can make decisions using application data such as HTTP host, path, or cookies |

Health checks can remove unhealthy backends from rotation. Sticky sessions keep a client associated with a backend when the application requires it. Some load balancers also terminate TLS, meaning traffic may be decrypted at the balancer before being forwarded to backend servers; understand where encryption is applied in the architecture.

A load balancer is not automatically a firewall, authentication system, or endpoint-protection control. It can also affect reconnaissance: scans may reach different backends, and the public-facing address may not reveal the backend server addresses.

## 6. Recon-to-enumeration workflow
1. Confirm the target and written scope.
2. Identify local interface, address, and route.
3. Discover live hosts using an appropriate method.
4. Scan authorized hosts for TCP/UDP ports.
5. Identify services and versions.
6. Enumerate each service using protocol-specific methods.
7. Record evidence and prioritize likely weaknesses.
8. Only then consider controlled validation or exploitation.

ip -br address
ip route
ip neigh
~~~

## 7. IPv4, IPv6, and CIDR
The practical notes describe IPv4 as a 32-bit address written as four decimal octets, each ranging from 0 to 255. A subnet mask separates network bits from host bits.

Example: `192.168.1.10/24` means the first 24 bits identify the network and the remaining 8 bits are host bits. CIDR uses a flexible prefix length rather than relying on historical address classes.

| Prefix | Subnet mask | Usable IPv4 hosts in a conventional subnet |
|---:|---|---:|
| /8 | 255.0.0.0 | 16,777,214 |
| /16 | 255.255.0.0 | 65,534 |
| /24 | 255.255.255.0 | 254 |
| /30 | 255.255.255.252 | 2 |

For ordinary IPv4 subnets, the standard host-count shortcut is:

\[2^{(32-prefix)}-2\]

The subtraction accounts for the network and broadcast addresses in conventional subnets; special cases exist, so use the addressing plan and subnet context.

IPv6 uses 128-bit addresses written in hexadecimal groups separated by colons. Leading zeros in a group may be omitted, and one consecutive run of zero groups may be compressed with `::`. IPv6 common IPv6 address types are unicast, multicast, and anycast; IPv6 does not use broadcast.

IPv6 includes support for IPsec, but that does not mean all IPv6 traffic is automatically encrypted or authenticated; support and actual deployment are separate matters.

## 8. Switching, VLANs, and routers

### Switches
A Layer 2 switch forwards Ethernet frames using a MAC address table (CAM table). It learns the source MAC address and incoming port; a known destination is forwarded to its port, while an unknown destination is flooded within the VLAN.

- Each switch port is its own collision domain.
- A VLAN creates a separate logical broadcast domain.
- An access port carries one VLAN for an end device.
- A trunk carries multiple VLANs and commonly uses 802.1Q tagging.
- Inter-VLAN communication requires a router or Layer 3 switch.
- Spanning Tree Protocol (STP) prevents Layer 2 loops and broadcast storms.

MAC flooding targets the switch's MAC address table. Port security can limit the number of MAC addresses learned on a switch port and help reduce this risk.

### Routers and routing tables
A router is a Layer 3 device that forwards packets between networks using destination IP addresses and a routing table. The table contains destination networks, masks/prefixes, next hops, and interfaces.

Common route types include directly connected, static, default, and dynamic routes. The default route is written as `0.0.0.0/0` for IPv4. A host uses its default gateway when the destination is outside its local subnet.

Routers separate broadcast domains and do not forward ordinary ARP broadcasts. They use ARP on the local link to resolve the MAC address of the next hop.

### Inter-VLAN routing and NAT
Router-on-a-stick uses one physical router interface with multiple VLAN-tagged subinterfaces. A Layer 3 switch can also route between VLANs.

The practical notes distinguish:
- **Static NAT:** one private address mapped to one public address.
- **Dynamic NAT:** private addresses mapped from a pool of public addresses.
- **PAT / NAT overload:** many private hosts share one public address using transport identifiers; common in home routers.

TTL is reduced by each router hop. When it expires, the packet is discarded and an ICMP Time Exceeded message may be returned; this behavior is used by traceroute.

## 9. TLS, SSL, and HTTPS
Encrypted transport is needed because without it, a person able to sniff traffic may read credentials and other transmitted data.

- **SSL** is deprecated; SSL 2.0 and SSL 3.0 are insecure.
- **TLS** is the modern successor. The notes identify TLS 1.2 and TLS 1.3 as versions to recognize.
- TLS aims to provide confidentiality, integrity, and authentication for the connection.
- A server certificate binds a domain identity to a public key and is validated through a certificate chain anchored in a trusted root CA.
- HTTPS means HTTP carried over TLS. The browser padlock indicates a protected channel; it does not mean the website itself is trustworthy or free of vulnerabilities.

TLS key establishment differs by version and cipher suite. A useful high-level distinction is that asymmetric cryptography supports authentication and key establishment, while symmetric cryptography protects bulk application data.

## 10. Packet inspection with Wireshark
The practical notes use Wireshark to inspect captured traffic and filter packets. Common display filters include:

~~~text
arp
ip.addr == 10.0.0.5
tcp
udp
dns
http
~~~

A display filter changes which captured packets are shown. It does not change the packets in the capture file. Inspect packet direction, source/destination addresses, protocol fields, and whether application data is protected by TLS.

## 11. Ethernet and Wi-Fi basics
Ethernet and Wi-Fi use different transmission media and have different security considerations.

- **Ethernet** carries frames over a physical medium such as copper or fiber. Physical access to the cable/switch port is an important part of the security boundary.
- **Wi-Fi** carries traffic over radio waves, allowing mobility but exposing the wireless medium beyond the physical cable boundary.
- Ethernet-related risks include such as ARP spoofing and MAC flooding, and Wi-Fi risks such as evil-twin access points, deauthentication, and weak WPA/WPA2 configuration.

### Managed mode versus monitor mode
- **Managed mode** is the normal client mode: the wireless card associates with an access point and participates in the network.
- **Monitor mode** allows a compatible wireless adapter to capture 802.11 frames without associating as a normal client. Support depends on the adapter, driver, and operating system.

Tools used for wireless analysis include airmon-ng, airodump-ng, aireplay-ng, and Wireshark. Their use can disrupt wireless networks or capture sensitive traffic; only use them on your own lab network or with explicit authorization.

## 12. Cryptography fundamentals

The second study PDF introduces cryptography, encryption, hashing, and common algorithms. These concepts help explain why HTTPS protects traffic and why password hashes are handled differently from plaintext passwords.

### Encoding, encryption, and hashing

| Concept | Reversible? | Key required? | Main purpose |
|---|---|---|---|
| Encoding (for example, Base64) | Yes | No | Represent data in another format; it is not encryption |
| Encryption | Yes, with the appropriate key | Yes | Protect confidentiality by converting plaintext into ciphertext |
| Hashing | Designed to be one-way | No secret key for an ordinary hash | Produce a fixed-length digest for integrity checks and other uses |

Do not treat Base64 as a security control. Anyone who has the encoded value can decode it.

### Symmetric and asymmetric encryption

- **Symmetric encryption:** the same secret key is used to encrypt and decrypt. It is efficient for protecting larger amounts of data. AES is a widely used modern example; DES is obsolete.
- **Asymmetric cryptography:** uses a mathematically related public/private key pair. It supports authentication, digital signatures, and key-establishment mechanisms. RSA and elliptic-curve cryptography are common examples.

Modern TLS uses asymmetric cryptography and certificates to authenticate the server and establish shared session keys; bulk application data is then protected using symmetric authenticated encryption. Exact handshake details depend on the TLS version and cipher suite.

### Hashes and password storage

A hash function maps input data to a fixed-length digest. For a given algorithm, the same input produces the same digest, while a small input change should produce a substantially different output.

| Algorithm / scheme | What to know |
|---|---|
| MD5 | 128-bit digest; unsuitable where collision resistance is required |
| SHA-1 | 160-bit digest; no longer considered collision-resistant |
| SHA-256 | 256-bit digest, normally shown as 64 hexadecimal characters |
| bcrypt | Adaptive password-hashing function designed for password storage |
| NTLM | Windows challenge-response authentication protocol and associated password-hash format; legacy NT hashes are weak against offline guessing |

A general-purpose hash such as SHA-256 is **not** an appropriate password-storage scheme on its own. Password databases should use a dedicated, salted, deliberately expensive password-hashing scheme such as bcrypt, scrypt, or Argon2, with a suitable work factor.

Hashing is one-way; cracking attempts to find a candidate input that produces the stored hash. A successful match reveals a candidate password, not a reversal of the hash function.

### Certificates and trust

A digital certificate binds an identity (such as a DNS name) to a public key and is signed by a certificate authority. Browsers validate the certificate chain, hostname, validity period, and other constraints before trusting the server identity. A valid certificate does not prove that the website itself is safe or free of vulnerabilities.

## 14. Quick recap
- IP is used for network-layer addressing; MAC is used on the local link.
- ARP maps local IPv4 addresses to MAC addresses.
- DNS maps names to records; TCP is reliable and connection-oriented; UDP is connectionless.
- Common ports guide enumeration but do not prove the service.
- Sniffing observes traffic; MITM attempts to intercept or relay it.
- ARP spoofing and rogue DHCP can redirect local traffic.
- Verify scope before scanning discovered assets.
