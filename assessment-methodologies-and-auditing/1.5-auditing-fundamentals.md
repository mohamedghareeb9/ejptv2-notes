## 1. What an audit is
A security audit is a structured review of systems, configurations, processes, and controls. A penetration test actively evaluates whether weaknesses can be used to affect a system; an audit may also examine whether required controls exist, are configured, and are followed.

The practical notes introduce defensive controls that a tester should recognize: network and host firewalls, IDS/IPS, endpoint protection, EDR, DHCP snooping, and cryptography.

## 2. Control types

| Control | Main purpose | Limitation |
|---|---|---|
| Packet-filtering firewall | Filters packets using addresses, ports, and protocol | Basic stateless rules do not understand the full application conversation |
| Stateful firewall | Tracks connection state | An allowed connection can still carry malicious application data |
| Proxy/application firewall | Mediates or inspects application traffic | Requires suitable protocol/application support |
| NGFW | Combines stateful filtering with application awareness and inspection | Not a substitute for secure endpoints or applications |
| IDS | Detects suspicious traffic and alerts | Detection alone does not block traffic |
| IPS | Detects and can block suspicious traffic | Incorrect rules can disrupt legitimate traffic |
| EDR | Monitors endpoint behavior and supports response | Does not replace patching or least privilege |

**Firewall** filters according to policy. **IDS** observes and alerts. **IPS** can prevent selected activity. A firewall does not automatically fix weak passwords, phishing, vulnerable applications, or compromised endpoints.

## 3. Endpoint security
An endpoint is a network-connected device such as a laptop, workstation, server, phone, VM, or IoT device.

Typical endpoint attack surface:
- Listening services and open ports.
- Installed and outdated software.
- Local users, groups, and permissions.
- Stored credentials and sensitive files.
- Remote access services such as SSH, RDP, and SMB.

Traditional controls include antivirus, host firewalls, and OS updates. EDR adds behavior monitoring, centralized visibility, and response actions such as terminating a process or isolating a host.

## 4. Network infrastructure controls

### DHCP security
DHCP automatically supplies network configuration. A rogue DHCP server may offer a malicious gateway or DNS server. DHCP starvation attempts to consume the available address pool.

The practical notes identify DHCP snooping as a switch-level defense: administrators mark DHCP-server-facing ports as trusted and restrict server replies from untrusted ports.

### Load balancers
A load balancer distributes incoming traffic across backend servers. It can improve availability, perform health checks, and keep a client attached to the same backend using session persistence.

- Layer 4 balancing uses transport-layer information.
- Layer 7 balancing can make decisions using application-layer information.
- A load balancer is not automatically a firewall or authentication system.
- It can hide backend addresses and make repeated scans appear to reach different servers.

## 5. Cryptography concepts
| Concept | Reversible? | Key required? | Typical purpose |
|---|---:|---:|---|
| Hashing | No | No | Integrity checks and password verification |
| Encryption | Yes, with the right key | Yes | Confidentiality |
| Encoding | Yes | No | Data representation and compatibility |

The practical PDF describes symmetric encryption (same key for encryption and decryption) and asymmetric encryption (a public/private key pair). AES is given as a symmetric example; RSA and ECC are asymmetric examples. Base64 is encoding, not encryption.

**External clarification:** the source's one-line statement that hashing protects integrity is a useful memory aid, but password storage normally requires a dedicated password-hashing scheme rather than a fast general-purpose digest.

## 6. Audit workflow
1. Define authorized scope and objective.
2. Identify assets and relevant controls.
3. Collect configuration and observable evidence.
4. Compare evidence with the expected policy or baseline.
5. Record the finding, affected asset, evidence, impact, and remediation.
6. Retest after remediation and record the result.

Separate observed facts from assumptions about impact.

## 7. Self-check
1. How does an IDS differ from an IPS?
2. Why is a firewall not a complete security solution?
3. What does DHCP snooping help defend against?
4. Why is a load balancer not the same as a firewall?
5. Which of hashing, encryption, and encoding requires a secret key?
6. Why should an audit finding distinguish evidence from assumptions?

## 8. Quick recap
- Firewalls filter; IDS alerts; IPS can block; EDR monitors endpoint behavior.
- DHCP snooping helps defend against rogue DHCP behavior.
- Load balancers distribute traffic and perform health checks; they are not inherently security boundaries.
- Hashing, encryption, and encoding are different operations.
